# 12：缺口历史、已阅确认与持续告警

本文定义采集缺口从故障信号到管理员可见历史及已阅交互的完整生命周期。

**What to build:** 管理员能判断某段历史可能不完整、故障是否仍在发生以及告警是否已阅；恢复和确认都不能抹去未到期缺口或隐藏活动故障。

**Blocked by:** 10 — 总预算、满额暂停与自动恢复；11 — 异步采集故障与异常重启。

Status: ready-for-agent

**Spec:** [请求输入审计 spec](../spec.md)。主要覆盖 User Stories 17、48、54–58。

## Acceptance criteria

- [ ] 汇集解析失败、未知块导致不完整、队列满、容量暂停、写入失败、不兼容及异常重启的不确定性，管理页持续可查看，不仅出现在日志。
- [ ] 未监控、主动暂停、纯工具续跑和真正空输入为预期跳过，不增加丢失计数；已标记容量截断不冒充完整，但不混淆为整条写入失败。
- [ ] 显示缺口原因、时间范围、可确定计数及当前状态；未知数量或范围明确标记不确定，不报告虚假的精确数或零损失。
- [ ] 缺口历史跟随输入保留期限，默认七天；已恢复缺口在到期前仍可查看，尚未恢复的故障不因历史到期隐藏。
- [ ] 管理员可以确认已阅以减少重复提醒，但不能因此删除历史、隐藏活动故障或改变完整性结论；出现新缺口或故障再次发生时重新提醒。
- [ ] 事件、汇总与已阅状态均有界，在总预算内；空间紧张时可保守聚合但不能伪装没有缺口，不挤掉未过期输入。
- [ ] 缺口持久化、管理输出和宿主诊断不包含原始认证 Key 或输入正文，不为了告警复制用户内容。
- [ ] 存储不可写时显示尽力而为的真实运行状态，恢复后不能把可能丢失的期间补报成完整；不可写或宿主宕机时不承诺管理页持续可用。
- [ ] 只有管理权限能查看和确认缺口；确认操作不影响采集配置、历史输入或宿主模型调用。
- [ ] 不接入邮件、Webhook、外部服务或自动违规判定，不将缺口告警变成内容审核结果。

## Testing decisions

利用前置票的容量和故障场景，经公开管理 API 与浏览器观察事件、恢复、到期和确认；控制时间验证活动故障和已恢复历史差异。验证有界持久化输出，避免私有表结构断言或生产告警注入后门。

## Implementation constraints

计数准确性不得高于实际可知范围，不以保存完整请求补偿。故障去重或聚合可以是实现细节，但公开状态必须保守真实，不能因已阅或自动恢复隐去新问题。
