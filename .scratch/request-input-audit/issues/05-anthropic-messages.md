# 05：Anthropic Messages 输入审计

本文定义 Anthropic Messages 的新用户内容与工具续跑边界，并将结果贯通到管理员页面。

**What to build:** 管理员可以查看 Anthropic Messages 本次末尾新用户输入；同为 user role 的工具结果续跑不会被误判为用户发言，混合新内容只保存允许部分。

**Blocked by:** 03 — Chat Completions 完整输入边界。

Status: ready-for-agent

**Spec:** [请求输入审计 spec](../spec.md)。主要覆盖 User Stories 11–24、26–28、40–41。

## Acceptance criteria

- [ ] 观察实际客户端提交的原始 Anthropic 协议输入，先于模型名业务改写、协议转换或执行路由；关联宿主已认证的客户端对象，不关联上游账号。
- [ ] 仅包含 tool_result 的末尾 user 消息正常跳过，不因 role=user 就保存，也不向前回找旧用户发言。
- [ ] 同一末尾 user 消息混合 tool_result 与新文本时仅保留新文本及允许非文本占位符；工具结果内部嵌套文本、图片、文件和引用均不提取。
- [ ] 连续多个用户消息只取最后一条，不保存历史、system/developer 指令、模型回复或工具调用。
- [ ] 已识别非文本块只保存固定占位符；未知块报告提取不完整或解析缺口；空输入、仅空白和普通文本秘密遵循既定规则。
- [ ] 64 KiB UTF-8 安全前缀仅影响审计副本；管理列表和详情正确显示协议、请求模型、正文及截断或不完整状态。
- [ ] 可提取输入的执行前路由失败不漏出观察范围；认证失败和未监控提交不记录；采集不等待模型回复成功。
- [ ] 可控上游验证原请求不被审计改写、截断或拦截；持久化与诊断专项检查验证禁止内容不被额外保存。

## Testing decisions

通过真实 Anthropic HTTP 提交、受保护管理 API 与少量页面验收，覆盖纯文本、仅工具结果、混合工具结果与新文本、工具结果内嵌图片、未知块、空白和截断。预期使用独立夹具，不查询私有数据库结构。

## Implementation constraints

不能以转换后的 OpenAI 消息列表推断 Anthropic 最新输入。对无法识别的格式保守报告问题，不序列化完整请求或工具结果作为回退。
