# 03：Chat Completions 完整输入边界

本文定义 Chat Completions 从客户端原始提交到管理员详情的内容提取、截断和隐私验收。

**What to build:** 管理员能够查看 Chat Completions 本次提交末尾最新一条新用户输入，正确识别工具续跑、非文本占位、未知块、空输入与 UTF-8 截断，不保存历史或其他禁止内容。

**Blocked by:** 01 — 最小安全 Chat Completions 审计闭环。

Status: ready-for-agent

**Spec:** [请求输入审计 spec](../spec.md)。主要覆盖 User Stories 11–24、40–41、54、59。

## Acceptance criteria

- [ ] 只取本次显式提交末尾新用户消息；末尾连续多个 user 只取最后一条，不跨消息拼接。末尾 assistant、工具调用或工具结果不倒序回找旧 user。
- [ ] 同一选中消息的允许文本和占位符按原顺序组合，工具内容及嵌套工具结果不提取；历史、system/developer、模型回复、工具调用或结果不保存。
- [ ] 已识别图片、音频、视频、文件等只保存固定占位符，不保存载荷、文件名、URL、Base64 或引用标识；仅图片等输入仍可形成占位符记录。
- [ ] 普通文本中的链接、Base64 或秘密仍原样保存，不进行启发式图片识别或通用脱敏，不把普通文本和协议非文本块混淆。
- [ ] 未知内容块不序列化保存；可安全提取的部分标记不完整并产生可见诊断，完全无法判断时报告解析缺口，不保存整请求作为回退。
- [ ] 真正空内容正常跳过且不报缺口；仅空白文本原样保存，不自动 trim。未知内容不能被归类为空而掩盖失败。
- [ ] 默认按文本与占位符合计 UTF-8 字节执行 64 KiB 前缀上限，不含元数据；恰好上限不误报，多字节字符不会被切断，超限尾部不持久化。
- [ ] 列表和详情明确显示截断或提取不完整，不宣称拥有完整输入；可查询正文只包含实际保存部分。
- [ ] 截断、未知块和解析失败不修改上游原请求，也不为审计拒绝调用；异步队列不暂存完整请求。
- [ ] 持久化输出和插件日志的专项检查验证禁止内容没有新增保存，而不是仅证明管理 API 不返回它们。

## Testing decisions

使用真实 Chat Completions HTTP 提交、受保护管理查询和可控上游，覆盖末尾角色排列、混合内容、非文本载荷、未知块、空白和 UTF-8 边界。预期来自独立夹具，不用提取器重算预期；不另立未经确认的提取器私有测试边界。

## Implementation constraints

普通正常跳过与解析缺口须区分；截断为已知容量限制，不冒充完整输入。本票建立的内容与状态语义供后续协议扩展复用，但不因复用需要提前实现全部协议。
