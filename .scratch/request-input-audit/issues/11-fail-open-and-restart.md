# 11：异步采集故障与异常重启

本文定义有界采集队列、存储故障、兼容错误和异常退出后可见的不确定性。

**What to build:** 管理员能识别队列或写入造成的采集缺口；模型调用不因可处理审计故障被拒绝。异常重启与观察能力不可用时显示真实状态，不把未知损失报告为零。

**Blocked by:** 01 — 最小安全 Chat Completions 审计闭环。

Status: completed

**Spec:** [请求输入审计 spec](../spec.md)。主要覆盖 User Stories 17、52–55、58–60。

## Acceptance criteria

- [x] 队列具有明确容量和压力行为，只包含已经提取、截断的副本，不包含完整请求或会话；队列满放弃该次审计并记录可确定缺口。
- [x] 解析、队列、接口与存储等可处理故障不拒绝或修改模型调用，不等待审计落盘；不声称同步输入观察没有任何处理延迟。
- [x] 队列未落盘数据不以已保存记录返回；写入成功、提取不完整、正常跳过和丢失之间能从公开管理状态正确区分。
- [x] 写入失败、只读目录或底层空间不可写时产生真实故障状态；不通过保存整请求或原 Key 作为排查日志泄漏内容。
- [x] 异常退出后能检测并提示可能存在未落盘输入；数量或时间范围无法确定时明确未知或不确定，不填零，不以持久化整请求追求精确计数。
- [x] 宿主观察接口缺失、版本不兼容或桥接不可用时停采并报告原因，不回退到执行层钩子冒充全覆盖；管理能力也缺失时启动诊断如实说明。
- [x] 模型正常调用在不兼容与常规故障场景仍保持原行为；故障恢复不抹去既有损失信号，配置和历史正常可恢复。
- [x] 基础故障状态可经管理 API 和页面查看，而非只写日志；没有条件持久化故障时仍尽力保留运行期状态和宿主诊断，不保证磁盘彻底不可写时告警必定落盘。
- [x] 明确原生同进程的进程级崩溃不隔离；本票验证常规 fail-open 和重启诊断，不将其描述为 native sandbox、exactly-once 或零丢失保证。

## Testing decisions

从真实请求与受保护状态查询观察结果，在隔离环境控制写入权限、存储失败、队列压力和异常进程退出；故障注入不能成为生产 API。检查公开响应和上游收到请求保持不变，异步完成等待明确条件。

## Implementation constraints

本票可以独立于全协议实现，在已有 Chat 链路验证通用故障机制。容量策略由对应 ticket 实现，完整缺口聚合、保留和已阅交互在其后续 ticket 验收。不新增独立采集进程或外部通知。
