# 08：筛选、关键词搜索与安全浏览

本文定义管理员在现有管理入口中定位和查看独立输入记录的查询与展示行为。

**What to build:** 管理员按审计对象、服务端时间、请求模型和字面关键词组合查询，使用分页预览与单条详情查看记录；审计正文只能作为不可信纯文本展示。

**Blocked by:** 01 — 最小安全 Chat Completions 审计闭环。

Status: completed

**Spec:** [请求输入审计 spec](../spec.md)。主要覆盖 User Stories 33–41、59。

## Acceptance criteria

- [x] 页面和受保护 API 支持对象、时间范围、客户端请求模型名与关键词筛选，条件取交集；不把上游实际模型当作请求模型。
- [x] 关键词仅在实际保存正文中按字面子串匹配，英文忽略大小写、中文按字面；正则字符与搜索语法作为普通字符，不提供语义搜索。
- [x] 不搜索原 Key、未保存历史、超限尾部或非文本载荷，已存在的截断和不完整状态不被搜索结果掩盖。
- [x] 使用有界分页，不一次载入全部记录；列表提供短预览，详情只显示单次提交正文与允许元数据，不自动拼接或生成完整会话。
- [x] 已建立的到期可见性规则应由查询共同遵守；后续保留期 ticket 不需要重写另一套搜索到期逻辑。
- [x] 正文及名称等不可信内容不执行 HTML/脚本、不渲染 Markdown 图片、不自动加载或访问外部链接；恶意样式或管理员指令文本只是被审查内容。
- [x] 静态资源仅包含无数据页面 shell；输入、记录详情、名单、查询结果和状态均需宿主管理认证，匿名及普通客户端 Key 不可读。
- [x] 查询、页面及错误输出不额外暴露或保存原认证 Key、请求头、IP、会话标识或上游账号。
- [x] 在当时已支持的协议数据上完成独立验收；新增协议沿用该查询行为，最终票补全部协议的组合回归。

## Testing decisions

通过受保护查询 API 验证组合筛选和字面搜索，使用浏览器验证管理菜单、分页、详情、截断标记和恶意正文安全展示；检查没有外部内容加载。测试外部行为，不固定底层索引或 SQL 实现。

## Implementation constraints

本票不新增导出、批量下载、删除、自然人用户归属、富文本渲染或搜索语法。语言、UI框架和查询索引可按实际需要选择，不以新功能扩大保存范围。
