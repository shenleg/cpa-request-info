# 10：总预算、满额暂停与自动恢复

本文定义插件自有持久化预算、满额行为和空间恢复后续采的端到端可见规则。

**What to build:** 管理员看到实际占用与容量暂停原因；插件总存储受预算约束，满额不挤掉未过期历史，正常过期清理释放空间后恢复采集。

**Blocked by:** 09 — 保留期限与配置变更。

Status: ready-for-agent

**Spec:** [请求输入审计 spec](../spec.md)。主要覆盖 User Stories 45–51、54、56、60。

## Acceptance criteria

- [ ] 默认总持久化预算 1 GiB，涵盖正文、索引、数据库辅助文件、监控配置和健康/缺口数据；不只计正文，不允许辅助文件无限增长。
- [ ] 预算内为配置、诊断和必要维护预留空间，写入及后台维护空间需求可解释、可验证；正文在耗尽全部空间前暂停。
- [ ] 满额不删除未过期历史，不覆盖旧输入，不修改模型请求，只停止后续副本采集并产生可见缺口及容量原因。
- [ ] 页面与受保护管理状态显示配置预算、当前占用和采集状态；无法完全可写时不伪装为采集正常。
- [ ] 过期清理释放足够空间后自动恢复，保留先前容量缺口，不因状态切换擦除历史；主动暂停不会被空间恢复解除。
- [ ] 管理员可调整总预算且参数有限、受校验；降低到现有未过期占用以下时明确显示超预算并停止新采集，不提前删除历史以立即达标。
- [ ] 容量限制与单条上限、保留期和辅助状态共同工作，后台维护不通过临时文件绕开空间约束；恢复判定避免频繁抖动且理由明确。
- [ ] 在连续提交、重启、数据库辅助文件增长和过期清理场景下验证持久化有界；不承诺 1 GiB 可完整保存任意流量七天。
- [ ] 容量缺口的数据不含原 Key 或输入正文，预留空间或底层磁盘耗尽时告警持久化只能尽力，运行期状态仍尽力反映故障。

## Testing decisions

在隔离数据目录使用较小但合法的预算和可控时间，以真实请求填充、管理员查询、过期清理和配置降低观察暂停/恢复。检查持久化输出及辅助占用而不是断言某种数据库结构；通过可控上游验证调用不变。

## Implementation constraints

存储预算不包括宿主已有日志，但插件新增日志和其他持久化不能成为正文预算的逃逸通道。没有授权增加提前淘汰、导出、手动删除或外部存储。缺口历史和已阅交互由后续票完善，本票先提供真实容量信号及基础告警。
