# 13：可复现的本地交付与跨平台验收

本文定义完整第一版的宿主补丁、原生插件交付以及隔离系统验收门槛。

**What to build:** 部署管理员能够按明确步骤在支持的宿主基线上构建、加载和本地运行插件；完整系统在目标平台与三协议、WebSocket 上通过 spec 行为矩阵，并明确安全及故障局限。

**Blocked by:** 05 — Anthropic Messages 输入审计；06 — HTTP 调用失败、流式与重试的一次提交语义；07 — Responses WebSocket 消息级审计；08 — 筛选、关键词搜索与安全浏览；12 — 缺口历史、已阅确认与持续告警。

Status: open
Triage: ready-for-agent

**Spec:** [请求输入审计 spec](../spec.md)。覆盖全部行为验收矩阵及 User Stories 60–62。其他前置票由上述直接阻塞票传递约束，不重复列为直接依赖。

## Acceptance criteria

- [ ] 提供可复现的官方 v8.0.27 基线识别、最小宿主补丁应用和本地构建方式，清楚区分版本号、原生插件支持能力和新增观察契约。
- [ ] Linux amd64/arm64 原生插件和对应宿主能够构建并加载，macOS 开发链路可用；仅交叉编译成功不能宣称目标架构运行验收成功，未运行项必须明确报告。
- [ ] 提供隔离本地运行及功能验证方式，使用合成 Key、合成输入和可控上游，不接生产实例，不执行第三方下载脚本或让真实凭据进入测试产物。
- [ ] 管理菜单、对象选择、配置、记录浏览、组合搜索、截断状态和缺口交互在完整系统浏览器中可用，认证边界正确且审计文本不加载外部内容。
- [ ] 在 Chat Completions、Responses HTTP、Anthropic Messages 上回归正常、SSE、路由前失败、上游失败、超时、客户端断开、重试及一次提交语义；不能仅以 Chat 测试通过概括三协议。
- [ ] Responses WebSocket 回归多次提交、身份、历史补全前输入、工具续跑、控制/取消和配置下一提交生效，HTTP 握手不替代消息级观察验收。
- [ ] 完整回归 64 KiB、到期、暂停、重启、降预算、辅助文件空间增长、满额及故障恢复，证明采集不修改模型请求、不提前删除未过期历史。
- [ ] 对审计持久化输出、辅助文件、管理输出及插件诊断开展禁止内容检查：不新增保存原认证 Key、整请求、历史、指令、回复、工具数据、会话标识或非文本载荷；普通文本主动粘贴秘密仍属已告知风险。
- [ ] 不兼容或观察桥接失效时停采并明确诊断，没有有限覆盖钩子的静默回退；当前故障与历史缺口不被恢复或已阅抹去。
- [ ] 部署说明明确应用层不加密、受限文件权限、主机/数据卷/备份访问边界、逻辑删除非安全擦除、同进程 native 风险以及常规 fail-open 的范围。
- [ ] 报告实际构建、加载、运行、测试与未验证项，不宣称吞吐、连续高峰七天保存、零丢失、零延迟或进程级隔离；性能目标留待后续测量。
- [ ] 不修改真实 .env、密钥、证书或 CI/CD，不进行生产部署、公开发布、git commit/push；这些操作仍需单独明确授权。

## Testing decisions

执行 spec 的系统行为验收矩阵，并补完整浏览器和目标平台加载/运行检查。隔离 Docker 本地验证可使用已允许的本机环境，但不等于授权生产操作；目标架构运行若需仿真应明确区别于原生执行。记录实际结果，失败和跳过都如实报告。

## Implementation constraints

这是一张完整交付验收票，不替代每张前置票自身的测试和隐私保护。发现未满足的前置行为应修复或明确阻塞交付，不能为方便验收静默改写父 spec 或降低需求。清理文件、容器数据或工作目录仍遵守用户的删除确认规则。
