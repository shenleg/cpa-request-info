# 09：保留期限与配置变更

本文定义记录到期、周期清理和管理员调整保留期及单条上限时的端到端行为。

**What to build:** 输入默认从服务端接收提交时起保留七天；到期立即退出查询，后台清理释放空间。管理员可安全调整保留与采集参数，不因暂停、停机或配置变更延长历史或改写旧正文。

**Blocked by:** 01 — 最小安全 Chat Completions 审计闭环。

Status: ready-for-agent

**Spec:** [请求输入审计 spec](../spec.md)。主要覆盖 User Stories 10、40–44、49–51、60。

## Acceptance criteria

- [ ] 默认七天，从宿主接收提交的服务端时间起算，不采信客户端时间，不从异步落盘或重启时重新起算。
- [ ] 到期后列表、详情和已有查询入口均不再暴露正文；物理删除由后台周期清理完成，不能因清理尚未运行就继续可查。
- [ ] 暂停、移除监控和停机不冻结期限；重启后处理已过期数据，不重新给予记录七天寿命。
- [ ] 管理员通过受保护 API 与页面修改保留期和单条上限，输入须有明确有限范围与非法配置错误，不能接受无界值。
- [ ] 缩短保留期须明确展示现有历史将提前到期的影响并经管理员确认；不能用未确认写入默默触发历史清理。
- [ ] 单条上限调整只作用于新提交的配置快照，旧正文不重新截断；历史元数据和内容不被静默改写。
- [ ] 配置及保留行为重启后保持；到期与清理可通过外部查询和隔离持久化输出观察，不依赖数据库私有表。
- [ ] 不提供手动清空对象、全量删除或提前删除未过期历史的管理功能。
- [ ] 页面或部署说明明确逻辑删除与空间回收不等于磁盘、数据库空闲页、快照或备份安全擦除，应用层不加密。
- [ ] 留出后续总预算配置与已有查询入口共用语义，不要求等待搜索票才完成最小列表和详情的到期验收。

## Testing decisions

在隔离测试环境控制服务端时间，提交记录并通过管理 API 检查到期前后、暂停和重启；不等待真实七天，不增设生产时间修改后门。缩短期限确认通过公开管理操作与少量页面验收。

## Implementation constraints

配置校验范围属于实现细节，须明确理由，不宣称此前已经选定具体上下界。实际实施中的清理测试需仅针对授权的隔离测试数据，不把本票范围等同于删除真实文件或生产历史的授权。
