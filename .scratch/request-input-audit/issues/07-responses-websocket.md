# 07：Responses WebSocket 消息级审计

本文定义已认证 Responses WebSocket 连接内每次客户端模型提交的审计边界和配置生效行为。

**What to build:** 管理员可逐次查看一个 WebSocket 连接中的用户提交，不把连接握手、控制消息或宿主恢复的历史当作新输入；名单与采集配置在下一次提交生效。

**Blocked by:** 02 — 监控对象与采集配置生命周期；04 — Responses HTTP 输入审计。

Status: ready-for-agent

**Spec:** [请求输入审计 spec](../spec.md)。主要覆盖 User Stories 11–24、29–32、40–41、52–54。

## Acceptance criteria

- [ ] 在真实 Responses WebSocket 消息处理链路，先于历史补全、协议业务改写和模型执行观察每次客户端模型提交；不是仅记录 HTTP 握手或执行层还原 body。
- [ ] 使用宿主对连接的实际认证身份匹配内置客户端审计对象，不重新猜测消息携带的 Key，不额外修改宿主握手或连接鉴权规则。
- [ ] 每次合格模型提交使用宿主生成的独立提交标识；同连接多次提交分别显示，内部重试不新增记录，不持久化连接或会话标识以合并历史。
- [ ] 本次显式新用户内容依 Responses 规则提取；字符串、结构化内容、图片等占位符、未知块、空白和截断保持既定语义。
- [ ] 不回查 previous_response_id、不从宿主恢复的历史补正文；本次显式重发旧文本仍按新提交独立记录。
- [ ] 握手、控制消息、取消事件与纯工具结果续跑不产生输入记录，不回找旧 user；取消或断开不删除此前已接收的合格输入记录。
- [ ] 名单添加/移除、名称、全局暂停和单条上限变更在下一次提交采用当前配置快照，无须重连；已入队副本不受后续变更追溯影响。
- [ ] WebSocket 消息解析或采集故障不为审计终止连接或模型调用，产生基础可见诊断；未知事件不序列化保存完整消息兜底。
- [ ] 管理页面逐条显示记录及状态；可控上游与客户端公开事件证明审计不改变原提交及宿主原有执行语义。
- [ ] 对插件存储和诊断检查，不新增保存原 Key、会话标识、原始整帧、历史、工具结果或非文本载荷。

## Testing decisions

通过真实 WebSocket 客户端建立连接并发送多次请求，使用管理 API 验证记录；覆盖工具续跑、控制/取消、previous_response_id、配置中途修改、重发和断开。保持原外部系统行为边界，不把 handler 私有状态作为合同。

## Implementation constraints

WebSocket 需要单独的消息级观察契约，HTTP 握手标识不能替代提交标识。若实际宿主事件语义与静态假设不同，应明确验证和必要技术调整，不静默降低已确定的新输入与故障边界。
