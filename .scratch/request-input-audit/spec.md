# 按 API Key 关联的请求输入审计插件

Status: ready-for-agent

本文定义第一版输入审计插件的需求、实现约束和验收边界，作为后续拆分实现 issue 的依据；不代表宿主扩展或插件能力已经实现、构建或运行验证。

- 整理日期：2026-10-13。
- 需求来源：本轮需求质询 Q1–Q32 及测试边界确认。
- 项目阶段：仓库尚无业务代码、测试或构建配置；本轮只生成 spec。
- 基线：官方 CLIProxyAPI v8.0.27 中支持原生插件的构建，配合本项目所需的最小宿主扩展。

## Problem Statement（问题陈述）

管理员需要在其管理且有权审计的单实例 CLIProxyAPI 上，对指定 API Key 提交的最新用户输入进行事后人工内容审查。使用者已经被告知会记录输入。

已有用量分析可以展示模型、token、延迟和客户端 Key 等逐请求信息，但不等于记录用户输入。直接启用全量请求日志再筛选也不符合本项目的数据最小化要求：它会先保存历史消息、系统指令或其他不应保存的内容。

审计需要同时满足：

1. 正确关联到宿主已经认证的客户端 API Key，而不是上游凭据、任意请求头值或自然人身份。
2. 只保存本次提交末尾的新用户输入，不回找旧发言，不重建完整会话。
3. 审计失败不能作为拒绝模型调用的理由，但管理员必须知道采集状态和历史缺口。
4. 限制本地持久化范围、保留时间和总存储占用。
5. 复用现有管理入口和管理鉴权，而非向普通 API Key 持有者开放查询。

## Solution（解决方案）

在固定宿主基线上增加最小的只读入站观察契约，由原生插件负责协议输入提取、有界异步持久化、采集健康状态和管理查询页面。

HTTP 的观察位置必须在客户端鉴权成功之后、协议业务改写和模型路由之前。Responses WebSocket 的观察单位是连接内每次客户端模型提交，位置必须在宿主还原历史上下文或执行模型请求之前。观察接口必须提供可信的已认证客户端身份以及本次提交的输入来源，不能用用量事件或上游认证信息代替。

管理员从宿主内置客户端 Key 的无秘密标识列表中选择监控对象并填写易读名称。默认不监控任何对象。每次符合条件的客户端提交最多产生一条独立输入记录。插件通过宿主托管菜单、页面和受管理鉴权保护的 API 提供筛选、搜索和缺口查看。

默认保留七天，单条正文最多 64 KiB，总持久化预算 1 GiB。满额暂停新采集，不提前删除未过期历史；过期清理腾出足够空间后自动恢复，但管理员主动暂停不会自动解除。

### 领域术语

| 术语 | 含义 | 不等同于 |
| --- | --- | --- |
| 客户端 API Key | 宿主内置 `api-keys` 中用于认证模型调用的 Key | 管理 Key、上游服务凭据、自然人用户 |
| 管理 Key | 宿主用于验证管理操作权限的凭据 | 客户端 API Key |
| 审计对象 | 由一个客户端 API Key 对应的稳定无秘密标识所代表的审查对象 | 易读名称、配置列表下标、上游账号 |
| 易读名称 | 管理员为审计对象设置的可修改标签 | 身份或历史关联依据 |
| 客户端提交 | 一次 HTTP 模型请求，或已认证 WebSocket 连接内一次客户端模型提交 | 上游重试、连接握手、完整会话 |
| 最新用户输入 | 本次客户端提交末尾明确包含的新用户发言中的允许内容 | 倒序找到的旧发言、宿主补回的历史上下文 |
| 输入记录 | 单次符合条件的客户端提交产生的受限正文及必要元数据 | 完整请求日志、完整会话、模型回复 |
| 预期跳过 | 未监控、主动暂停、纯工具续跑、无可审查内容等按规则不采集的情况 | 审计缺口 |
| 审计缺口 | 应当采集或应当能够判断的提交因采集能力、解析、队列或存储故障未被完整记录的情况 | 主动暂停、未监控对象 |

## User Stories（用户故事）

1. 作为管理员，我希望默认监控名单为空，以便部署插件不会自动采集所有调用者的输入。
2. 作为管理员，我希望选择宿主内置客户端 API Key 对应的无秘密标识，以便准确指定监控对象而不在插件中再次暴露原始 Key。
3. 作为管理员，我希望为监控对象填写易读名称，以便浏览时识别其业务用途。
4. 作为管理员，我希望修改名称后历史和新记录统一显示当前名称，以便不因改名拆散历史。
5. 作为管理员，我希望相同 Key 从名单移除后再次加入时沿用审计对象，以便查询仍在保留期内的历史。
6. 作为管理员，我希望不同原始 Key 即使使用相同名称也保持独立，以便轮换 Key 不造成自动历史归并。
7. 作为管理员，我希望监控选择不改变宿主的 Key 配置或认证逻辑，以便审计不成为 Key 管理功能。
8. 作为管理员，我希望能全局暂停采集，以便停止保存新输入而不立即删除历史。
9. 作为管理员，我希望移除监控对象不删除其未过期记录，以便仍能进行事后审查。
10. 作为管理员，我希望暂停和移除监控不冻结保留期限，以便数据不会无限期滞留。
11. 作为管理员，我希望只记录本次提交末尾最新一条新用户消息，以便不保存完整历史。
12. 作为管理员，我希望末尾连续多个用户消息只保留最后一条，以便不跨消息合并输入。
13. 作为管理员，我希望纯工具续跑不回找并重复记录旧用户发言，以便列表不制造虚假的新输入。
14. 作为管理员，我希望同一用户消息中只提取新文本和允许的非文本占位符，并排除工具结果，以便工具数据不进入审计。
15. 作为管理员，我希望图片只显示 `[图片]`，以便知道输入含图片但不保存图片载荷、URL 或 Base64。
16. 作为管理员，我希望音频、视频和文件等已识别非文本输入只显示固定占位符，以便不保存附件载荷、文件名、链接或引用标识。
17. 作为管理员，我希望未知内容块不被序列化保存，并明确显示提取不完整，以便不误以为记录完整。
18. 作为管理员，我希望普通文本原样保存而不进行通用自动脱敏，以便明确知道用户粘贴的秘密、链接或 Base64 字符串可能随文本保留。
19. 作为管理员，我希望不保存 system/developer 指令、模型回复、工具调用及工具结果，以便限制审计内容范围。
20. 作为管理员，我希望没有已识别文本或非文本占位符的空输入正常跳过，以便列表不充斥空记录。
21. 作为管理员，我希望仅含空白的文本不被自动 trim，以便记录准确反映提交内容。
22. 作为管理员，我希望每次客户端提交独立查看，以便不自动重建或合并完整会话。
23. 作为管理员，我希望客户端重复提交相同文本分别记录，以便不会因内容去重漏掉真实提交。
24. 作为管理员，我希望宿主内部重试和上游账号切换不重复记录，以便一个客户端提交最多对应一条输入记录。
25. 作为管理员，我希望已认证且可提取输入的请求在模型调用失败、超时或客户端断开时仍可记录，以便审计对象是提交行为而非成功响应。
26. 作为管理员，我希望模型路由前就失败的已认证请求也能进入观察边界，以便不因执行层提前返回造成隐蔽漏记。
27. 作为管理员，我希望 OpenAI Chat Completions、Responses 和 Anthropic Messages 均受支持，以便三协议采用一致的审查规则。
28. 作为管理员，我希望普通 HTTP 和 SSE 流式调用均受支持，以便采集不依赖模型回复形式或完成时间。
29. 作为管理员，我希望 Responses WebSocket 每次客户端模型提交独立审计，以便长连接内多次请求不被合并成一条。
30. 作为管理员，我希望 WebSocket 握手、控制消息、取消事件和纯工具结果续跑不成为输入记录，以便只保存允许的用户输入。
31. 作为管理员，我希望不回查 `previous_response_id` 或宿主补回的历史，以便隐私范围不因服务端会话状态扩大。
32. 作为管理员，我希望 WebSocket 连接中下一次提交采用最新监控和采集配置，以便暂停或移除监控无需等待重连。
33. 作为管理员，我希望复用现有管理入口和管理鉴权，以便不维护第二套登录或授权体系。
34. 作为管理员，我希望没有管理权限的请求不能读取记录、配置或缺口状态，以便敏感数据不因静态页面可访问而泄漏。
35. 作为管理员，我希望按审计对象、时间和客户端请求模型名筛选，以便定位待审查记录。
36. 作为管理员，我希望普通关键词按已保存正文的字面子串匹配，英文忽略大小写，以便无需学习搜索语法。
37. 作为管理员，我希望多个筛选条件取交集，以便查询范围符合预期。
38. 作为管理员，我希望列表显示短预览、详情显示单条已保存正文，以便快速浏览且不拼接会话。
39. 作为管理员，我希望 HTML、Markdown 图片和链接只作为不可信纯文本展示，以便审查内容不能执行脚本或加载外部资源。
40. 作为管理员，我希望单条超限时只截断审计副本的 UTF-8 前缀，并明确显示已截断，以便不修改模型实际收到的请求。
41. 作为管理员，我希望截断部分和未保存内容不可被搜索，以便搜索结果不暗示不存在的完整记录。
42. 作为管理员，我希望默认从服务端接收提交起保留七天，以便不相信客户端时间也不因写入延迟延长保存期限。
43. 作为管理员，我希望到期记录立即退出查询结果，后台周期清理物理记录，以便可见性和清理延迟有明确区别。
44. 作为管理员，我希望停机后重启不重新给予历史七天寿命，以便停机期间保留期限继续推进。
45. 作为管理员，我希望总预算涵盖正文、索引、数据库辅助文件、配置和缺口状态，以便不把无限增长的辅助数据排除在预算外。
46. 作为管理员，我希望预算中预留健康和缺口状态空间，以便正文容量耗尽时仍尽力提供诊断。
47. 作为管理员，我希望满额只暂停新审计，不提前删除未过期历史，以便已采集证据不被流量挤掉。
48. 作为管理员，我希望过期清理腾出足够空间后自动恢复采集，并保留此前缺口提示，以便恢复不掩盖损失。
49. 作为管理员，我希望可调整保留期、单条上限和总预算，以便适配部署条件。
50. 作为管理员，我希望缩短保留期前明确确认历史影响，以便了解部分历史会提前到期。
51. 作为管理员，我希望降低预算只触发暂停而不删除未过期记录，调整单条上限只影响新提交，以便配置变更不静默改写历史正文。
52. 作为管理员，我希望模型请求不等待审计落盘，以便队列或磁盘压力不成为拒绝模型调用的理由。
53. 作为管理员，我希望队列容量有限且只包含提取、截断后的副本，以便不无界积压完整请求。
54. 作为管理员，我希望解析、排队、写入和存储故障显示为缺口，以便区分未采集和正常无记录。
55. 作为管理员，我希望异常退出后显示可能丢失及未知数量，而不是零丢失，以便不把不确定性包装为完整审计。
56. 作为管理员，我希望缺口事件跟随输入保留期，而未恢复故障持续显示，以便历史到期不会隐藏当前故障。
57. 作为管理员，我希望可以确认已阅缺口但不隐藏未恢复故障，新缺口重新提醒，以便减少重复提醒而不抹去事实。
58. 作为管理员，我希望缺失观察扩展或采集不兼容时停采并明确告警，以便不悄悄降级成覆盖不完整的方案。
59. 作为管理员，我希望不额外收集 IP、User-Agent、其他请求头、会话标识或上游账号，以便审计不扩大成客户端追踪。
60. 作为部署管理员，我希望明确应用层不加密以及逻辑删除的局限，以便正确管理文件权限、磁盘保护、快照和备份。
61. 作为部署管理员，我希望 Linux amd64/arm64 可部署、macOS 可开发，并能先在隔离本地环境验证功能，以便不依赖生产实例试错。
62. 作为维护者，我希望第一版先通过隐私和失败边界验收而不承诺吞吐，以便性能目标依据后续实际测量制定。

## Implementation Decisions（实现决策）

### 1. 支持范围与宿主扩展

- 固定官方 CLIProxyAPI v8.0.27 为补丁基线；需要支持原生插件 ABI 且包含新增观察契约的宿主构建。版本号相同但不支持插件的构建不属于支持范围。
- 不承诺旧版本、其他 fork 或未来宿主升级自动兼容；升级需重新验证接口和审计语义。
- 第一版只监控宿主内置 `api-keys` 中的客户端 Key。不支持第三方 `frontend_auth` 身份、虚拟身份或上游账号映射。
- HTTP 观察在客户端鉴权成功后、协议业务改写、模型路由和执行前生效。WebSocket 在每次客户端模型提交被接收后、历史补全和执行前观察。
- 输入来源是解码后的原始协议内容，而不是压缩传输字节、协议转换后的消息、先前插件改写结果或宿主还原的会话。具体读取、解码和接入位置必须在实现阶段验证；读取异常只影响审计判断，不截断或破坏下游正常请求读取。
- 观察契约提供宿主生成的单次客户端提交标识、协议、服务端接收时间、必要的请求模型信息、可信的已认证身份及本次协议输入。不得用客户端自报 ID、任意 Authorization 值或上游 Auth 推断身份。
- 接口只读，不允许审计修改请求、路由、认证、响应或终止调用。内部重试和插件发起的嵌套执行不能伪装成新的客户端提交。
- 缺失扩展、不兼容或观察桥接不可用时停采并明确显示原因；不静默回退到有限覆盖的执行层钩子。宿主不支持管理注册时，至少通过启动诊断暴露不兼容，不能宣称管理页可用。

### 2. 安全身份与监控配置

- 宿主扩展提供稳定、不含原 Key 的审计对象标识和可选择列表；插件管理页面选择该标识并填写名称，不要求粘贴 Key，不返回原 Key 或原 Key 的字符片段。
- 宿主内部负责将最终认证结果映射到稳定标识。标识不是认证凭据，不能用于登录；关联不能依赖名称或可变配置下标。
- 原始认证 Key 不进入插件的持久化记录、监控配置、健康状态、接口输出或插件日志。内部认证和安全映射所需的瞬时处理不等于允许额外保存或展示原 Key。
- 名称修改后所有历史显示当前名称，不为每条记录保存名称快照。同一 Key 重新加入沿用稳定对象；不同 Key 不因同名、相同文本或业务用途自动合并。
- 名单默认空，支持添加、命名、移除监控对象及全局暂停。操作不修改宿主 Key 列表或鉴权策略；移除、暂停不删除未过期输入历史。
- 每次提交采用接收时的采集配置快照，已入队副本仍按该次快照处理。WebSocket 下一次提交采用最新名单、暂停状态和单条上限，连接身份来自宿主认证，不额外改变连接鉴权行为。

### 3. 最新输入提取

- 只判断本次显式提交的末尾新用户输入，不倒序寻找较早的用户消息，不跨消息拼接。
- 末尾连续多个用户消息只取最后一条；同一消息内的允许文本和非文本占位符可以按原内容顺序组合。
- 当末尾是 assistant、工具调用或工具结果续跑而没有新用户输入时正常跳过。Anthropic 的 `user` 消息如果只含 `tool_result`，同样跳过；不能仅凭 role 判断为新用户发言。
- 同一消息混合工具结果与新文本时忽略工具结果，仅保留允许的新内容。工具结果内部嵌套的文本或图片也不提取。
- Responses 字符串输入可表示本次新用户文本；结构化输入按末尾新用户规则处理。HTTP 与 WebSocket 均不得为 `previous_response_id` 回查历史，也不得从还原的上下文补齐审计正文。
- 客户端显式重发旧文本属于新提交，不猜测是否历史。客户端重复提交独立记录；不按文本、会话或客户端请求 ID 去重。
- 图片固定占位为 `[图片]`，其他已识别非文本内容采用 `[音频]`、`[视频]`、`[文件]` 等固定占位符。不保存其载荷、文件名、URL、Base64 或引用标识。
- 普通文本中的 URL、Base64、密钥或秘密不做启发式识别、清除或通用脱敏，仍可能原样保存。
- 未知内容块不序列化为正文；能够安全提取的已知部分可记录并标记提取不完整，同时产生可诊断的缺口状态。完全无法安全判断或提取时不捏造正文或标为正常完整，报告解析缺口。
- 没有已识别文本或占位符的真正空输入正常跳过。已存在但只包含空白的文本原样保存，不自动 trim。未知块不能被归入正常空输入以掩盖提取失败。
- 不保存 system/developer 指令、历史消息、模型回复、工具调用和工具结果；不保存整条原始请求作为解析回退或故障日志。

### 4. 记录与元数据

- 一次符合条件的客户端提交最多产生一条输入记录；宿主唯一提交标识用于保证内部重试不新增记录，不接受客户端控制唯一性。
- HTTP 请求与 WebSocket 的单次模型提交分别构成记录单位，不将整个连接作为一次请求。不持久化连接标识或会话标识来还原会话。
- 已通过认证且命中名单、能够提取新输入的提交，不依赖上游成功、失败、超时、流式完成或客户端仍在线。认证失败的请求不关联到某个审计对象。
- WebSocket 握手、控制消息、取消事件与纯工具结果续跑不产生输入记录；后续取消不能自动删除此前已接收的符合条件输入。
- 元数据仅包括插件记录标识、稳定审计对象标识、服务端接收时间、协议、客户端请求模型名及截断或提取状态等必要标记。
- 模型维度采用客户端请求的名称，不采用上游实际模型或账号。缺失或无法可靠确定时显示未知，不猜测或从模型回复补充。
- 不额外采集 IP、User-Agent、其他请求头、客户端用户标识、会话标识、上游账号或完整请求 URL。协议识别所需的瞬时传输信息不转为持久化追踪字段。

### 5. 存储、保留与预算

- 单实例本地持久化，不依赖外部数据库或聚合服务。具体语言、数据库和底层表结构尚未确定，不把候选实现描述为已决策架构。
- 默认保留七天，从服务端接收提交时起算，不采用客户端时间或异步落盘时间。暂停、移除监控和停机不冻结期限，重启不重置记录寿命。
- 到期记录从查询结果隐藏，物理删除由后台周期清理完成；启动和恢复必须处理过期数据。清理可以删除过期历史，不允许为了预算提前删除未过期记录。
- 默认正文上限 64 KiB，以提取后的文本与占位符的 UTF-8 字节数计算，不含记录元数据。保留前缀、不切断字符，明确标记已截断，列表和详情均可识别。
- 截断只作用于审计副本，不向宿主返回截断请求，不影响模型实际收到的字节或协议内容。历史记录不因单条上限降低而重新截断。
- 默认总持久化预算 1 GiB，涵盖插件自有输入记录、索引、数据库辅助文件、监控配置和缺口状态；宿主已有日志不纳入插件预算。不能把正文低于预算当作辅助文件可无限增长的理由。
- 预算内预留配置、健康状态和必要写入维护空间；正文采集在耗尽所有空间前暂停。实现须核算辅助文件和维护操作的空间需求，不承诺只统计正文就能限制磁盘占用。
- 若管理员把预算降低到已有未过期数据占用以下，停止新采集，不为立即达标提前删除历史；明确显示当前占用超出新预算。靠正常到期清理回到预算内。
- 容量足够后自动恢复满额导致的暂停，并保留此前缺口；不能自动解除管理员主动暂停。不因为容量抖动不断覆盖或抹除故障历史。
- 管理员可调整保留期、单条上限和总预算；参数须校验，具体可接受范围在实现中明确，不允许无界或非法配置。缩短保留期需确认现有历史的到期影响。
- 第一版不提供管理员手动删除未过期历史、按对象清空或全量清空功能。
- 应用层不加密正文，依赖管理员鉴权、受限文件权限和部署环境磁盘保护；主机高权限、数据卷和备份读取者仍可能读到正文。
- 到期采用逻辑删除及空间回收，不承诺数据库空闲页、文件系统、磁盘、快照或备份的安全擦除。部署管理员负责应用之外副本的保留策略。

### 6. 异步采集与故障边界

- 使用有界异步队列，模型调用不等待审计落盘。仅提取并截断后的副本进入队列，不能排队积压完整协议请求或整个会话。
- 允许队列满、存储故障和异常退出造成审计丢失；不承诺持久化 exactly-once、零丢失或零附加延迟。入队不等于已保存，管理查询不能伪装成已落盘记录。
- 可处理的解析、队列、存储和插件接口错误不能拒绝或改变模型调用，属于常规 fail-open；问题应产生健康状态和缺口诊断。
- 原生插件与宿主同进程，没有进程级隔离保证。非法内存访问、进程终止或其他不可恢复 native 故障可能影响宿主；第一版不增加独立采集进程。
- 插件停用、宿主故障或整机故障时，不能保证插件管理页仍可访问或每个丢失事件都可准确记数；应明确能力边界而非承诺无法实现的持续可用。
- 未监控、主动暂停、纯工具续跑和正常空输入为预期跳过，不计为缺口。解析失败、未知块导致的不完整、队列满、满额暂停和写入失败需要可见诊断。
- 单条已明确标记的容量截断是预期的记录限制，不冒充完整正文；其状态可识别，不等同于整条写入成功但内容完整。
- 缺口显示原因、时间范围及可确定的计数；无法准确确定的数量或时间边界明确标记未知或不确定，不填零，不伪造精确边界。
- 非正常退出后应标记可能存在未落盘输入；具体恢复检测机制在实现阶段验证，不能为精确计数额外持久化完整请求。
- 告警在管理页面持续可见，不仅写服务器日志；恢复后保留历史缺口。第一版不接邮件、Webhook 或其他外部通知。
- 缺口事件默认跟随输入保留期；尚未恢复的故障持续显示，不因历史到期被隐藏。告警不包含原始 Key 或输入正文。
- 支持已阅确认以减少重复提醒，但不能掩盖活动故障、删除缺口或把不完整历史改为完整；新缺口或再次故障重新提醒。
- 缺口与健康数据有界，空间紧张时可保守聚合，但不能伪装成没有缺口。底层磁盘完全不可写时不能保证告警持久化，应尽力通过现有运行期状态和宿主诊断显示真实故障。

### 7. 管理入口、查询与展示

- 复用宿主管理菜单、静态资源注册和受管理 Key 保护的管理 API，不建立普通客户端自助入口或第二套角色系统。
- 静态页面可以是公开的无数据 shell；记录、正文、配置、审计对象列表和健康状态必须通过受管理鉴权保护的接口获取，不能嵌入公开资源。
- 不额外持久化或在页面展示用于认证的原始管理 Key。沿用宿主既有认证流程不等于允许插件另存认证凭据。
- 页面脚本处于宿主同源管理信任边界，不能把管理员提交或用户输入当作可信脚本、模板、HTML 或可自动加载资源。
- 支持审计对象、时间范围、请求模型筛选及正文关键词查询，条件取交集。关键词为字面子串，英文忽略大小写，中文按字面匹配；不提供正则、搜索语法或语义搜索。
- 只搜索已保存且未到期正文，不搜索原始 Key、未保存历史、超限尾部或非文本载荷。
- 列表短预览，详情按请求查看正文及必要状态；不自动还原完整会话。采用有界分页查询，不一次载入全部历史。
- 未认证和仅持有普通客户端 API Key 的访问者不能查询敏感管理数据。

## Testing Decisions（测试决策）

### 已确认的主要测试边界

以系统外部行为为主：客户端通过 HTTP 或 WebSocket 提交，带最小扩展的宿主与插件处理，管理员通过受保护管理 API 查询输入记录和采集状态。用本地可控上游核对原始模型请求实际收到的内容，验证审计不修改或拦截调用。

这是行为验收边界，不把宿主钩子的私有方法、队列类、数据库表或辅助函数作为测试合同。没有批准独立提取器接口作为第二个必测边界；实现如需要改变测试边界，应先确认，不能暗中增加与私有实现耦合的大量测试。

### 测试质量要求

- 测试期望来自本 spec、明确输入夹具和独立预期值，不用被测提取逻辑重新计算预期。
- 正常请求以及应跳过、截断、提取不完整、失败恢复等边界均由公开行为观察。
- 时间、容量和存储故障在隔离测试环境控制，不为方便测试新增生产管理后门或故障注入 API。
- 异步测试等待明确的状态或结果条件，不依赖固定 sleep 或假定提交完成即落盘。
- 只检查管理 API 输出不足以证明禁止内容没有落盘。必须对持久化字段白名单和禁止内容设置专项检查；检查对外存储输出或隔离的数据目录，不以私有表名、索引名或内部查询作为主要合同。
- 对数据库辅助文件、恢复状态和插件诊断输出的检查需考虑隐私范围，不能在测试报告中复制真实 Key 或真实输入。
- 补充少量浏览器验收：管理入口、鉴权、筛选、详情、纯文本安全展示、截断和告警交互。
- 补充目标平台构建和加载验收：Linux amd64/arm64，macOS 开发环境；原生插件能力与宿主观察契约均需匹配。
- 当前仓库无已有测试或相似测试实现可引用；不存在可声称已复用的测试先例。

### 行为验收矩阵

| 验收主题 | 必须观察到的外部行为 |
| --- | --- |
| 默认与授权 | 空名单无输入记录；匿名和仅客户端 Key 不能访问敏感管理数据；静态页面不包含数据 |
| Key 归属 | 已认证的实际 Key 正确匹配；名称不作身份；名单或配置顺序变化不串对象；轮换不合并 |
| 名单生命周期 | 移除、暂停保留未过期历史；同一 Key 重新加入沿用对象；名称修改统一显示 |
| Chat Completions | 最后新用户文本可保存；连续用户只取最后一条；末尾 assistant/tool 不回找旧 user |
| Responses HTTP | 字符串及结构化输入遵循规则；不借 `previous_response_id` 获取历史；模型路由失败也进入观察边界 |
| Anthropic Messages | 仅 `tool_result` 跳过；混合新文本只保留允许部分；工具结果中的文本或图片不泄漏 |
| Responses WebSocket | 一个连接多次提交独立记录；原始本次提交先于历史补全；控制、取消和纯工具续跑跳过；下一提交应用配置变更 |
| 非文本与未知块 | 图片、音频、视频、文件只留固定标记；无载荷、URL、文件名或引用标识；未知块不序列化且状态不冒充完整 |
| 普通文本与空输入 | 文本中的秘密或链接不自动脱敏；真正空内容正常跳过；仅空白原样保存 |
| 重复与重试 | 客户端相同文本提交两次产生两条；上游重试、切换和嵌套执行不为原提交增加记录 |
| 失败与断开 | 上游成功、失败、超时或客户端断开不决定是否采集；认证失败不形成对象记录；无法解析时有缺口而非伪造正文 |
| 原请求不变 | 截断、队列满、解析或写入失败不改变上游实际收到的原请求，也不增加审计拒绝响应 |
| 64 KiB 边界 | 按 UTF-8 字节计算，包含占位符，不切断多字节字符；恰好上限不误报，超限前缀有明确标记 |
| 保留期限 | 服务端接收时间起算；到期查询隐藏；暂停和停机不冻结；重启不延长；后台清理空间 |
| 总预算 | 正文及辅助持久化有界；满额不删未过期历史；降低预算可以停采但不删历史；释放空间自动恢复而主动暂停不解除 |
| 异步与恢复 | 入队不冒充保存；有界队列压力产生缺口；写入故障不阻断正常调用；异常退出后提示可能丢失且未知不填零 |
| 缺口生命周期 | 故障恢复后仍有历史；未恢复故障不随保留期隐藏；已阅不掩盖故障；新增缺口重新提示 |
| 查询与显示 | Key、时间、请求模型和关键词取交集；只查已保存正文；正文不执行 HTML/脚本、不渲染外部图片或加载链接 |
| 持久化隐私 | 不新增保存原始认证 Key、完整请求、历史、系统指令、回复、工具数据或非文本载荷；含禁止内容的夹具不能出现在审计存储或日志 |
| 不兼容 | 缺失观察契约时采集不可用且状态明确；不以执行钩子悄悄降级；普通模型调用不因审计兼容错误被拒绝 |
| 部署 | 支持基线的原生插件构建可在目标Linux架构加载；本地验证使用隔离测试数据与上游，不触碰生产配置 |

### 验证阶段与非保证

- 先通过最小 HTTP 端到端链路验证观察位置、正确身份、原输入来源和调用不变，再逐步扩展协议、WebSocket 和故障场景。
- 第一版先做功能验证，不承诺请求吞吐、监控对象数量、搜索延迟或持续峰值能力；1 GiB 与七天不意味着任意流量都能完整保存七天。
- 原生进程级崩溃隔离不属于验收保证；逻辑删除不等于安全擦除。
- Docker 本地隔离验证已允许，但本次生成 spec 不启动部署。实际实现和验证不得据此授权生产部署或修改真实凭据、CI/CD。

## Out of Scope（范围外）

- 自动违规判断、LLM 审核、风险评分或内容分类。
- 修改或拦截模型请求、按内容拒绝请求、Key 封禁或修改宿主认证策略。
- 通用自动脱敏，包括猜测普通文本中的图片链接、Base64 或秘密并清除。
- 历史消息、系统或开发者指令、完整会话、模型回复、工具调用或结果的持久化与展示。
- 导出、会话重建、多实例聚合、远程集中存储或额外外部通知。
- 普通客户端 Key 自助门户、用户/RBAC/租户系统、自然人身份推断。
- 第三方前端认证提供方、上游账号或凭据的审计对象映射。
- 自动关联不同 Key 的轮换历史、名称快照、按内容或客户端 ID 去重。
- 手动清空历史、提前淘汰未过期记录、应用层正文加密和安全擦除保证。
- 独立采集进程、native 崩溃沙箱、零延迟或零丢失保证。
- 正则、搜索语法、语义搜索、自动加载或富文本渲染审计正文。
- 旧版或其他 fork 自动兼容、未核验的宿主版本升级和性能服务等级承诺。
- 本轮业务代码实现、实现 tickets 创建、生产部署、认证凭据或 CI/CD 修改，以及未经明确要求的 git commit/push。

## Further Notes（补充说明）

### 已核查的依据与结论范围

1. [官方插件开发指南](https://help.router-for.me/cn/plugin/development.html)：原生动态库与宿主同进程，支持管理 API、托管资源及菜单注册；公开静态资源与管理鉴权不是同一边界。
2. [官方 v8.0.27](https://github.com/router-for-me/CLIProxyAPI/tree/v8.0.27)：本轮固定版本源码核查发现，执行层请求钩子之前存在模型/provider 路由失败返回，不能把该钩子当作全部已认证入站的观察器；现有执行请求体也不保证是未改写的客户端输入。
3. [CPA-Manager-Plus 固定源码快照](https://github.com/seakee/CPA-Manager-Plus/tree/9d719fc8cca362f7b56d294a2ad056ae99cfeba6)：通过宿主 usage queue 持久化逐请求用量，不代理模型流量。官方用量链路可以传最终认证客户端 Key，但队列没有最新用户输入或客户端请求正文。不能把用量明细等同于输入审计，也不能声称官方完全无法识别客户端 Key。
4. [参考管理插件固定源码快照](https://github.com/Mxucc/cpa-account-config-manager/tree/ff3ff3299754021ddc6859444f32a076cd9b80d3)：可参考其原生插件、托管页面、菜单和受保护管理 API 集成方式；上游账号管理与本项目客户端 Key 输入审计不是同一领域。
5. 上述是静态文档和源码调查，不是本项目运行验证，不证明未来宿主升级或其他版本的全覆盖行为。

### 实现前后仍须验证的技术事项

- HTTP 的认证后观察位置、请求读取/解码方式以及业务改写前原始协议输入的正确传递。
- Responses WebSocket 消息级提交标识、连接已认证身份、事件类型和历史补全前的输入边界。
- 宿主无秘密稳定标识在配置顺序变化、移除/重新加入、重启与同值 Key 场景下不串联不同对象，也不暴露原始 Key。
- 内部执行重试、上游切换和嵌套调用不重复触发客户端审计。
- 原生 ABI、管理资源与观察契约的版本协商、不兼容停采及诊断。
- 异步队列、辅助持久化文件预算、过期清理、异常重启和不可写状态的可见缺口行为。
- 目标平台构建、加载以及最小宿主补丁的维护和升级成本。

这些是后续实现 issue 的验收任务，不是未决的业务需求，也不允许为了便利静默缩小已确认范围。
