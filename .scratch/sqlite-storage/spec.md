# SQLite 记录存储

将正式 HTTP 插件的记录主存储从分段 JSONL 改为内嵌 SQLite；保留采集、管理 API、保留期和故障语义，不迁移历史。

## 范围

- 新建独立 state-dir，旧目录原样保留；旧历史、监控对象、名称及设置均不导入。
- 内嵌 SQLite，不依赖数据库服务或系统 SQLite。公开接口、页面和过滤规则不变。
- 保留 64 条 / 8 MiB 非阻塞队列；事务持久提交后才计为保存和开放查询。
- 列表按提交顺序倒序；时间条件含端点；模型精确匹配；正文保持 ASCII 不区分大小写的字面子串搜索，包含 NUL、% 和 _。
- 默认 7 天、64 KiB 正文、整个目录预算 1 GiB，可调范围不变；过期立即不可查，维护实际释放空间，调长不延长旧历史。
- 主库、索引和实际保留的回滚日志都计费。采用单连接 PERSIST 日志、禁用 spill、小事务及增量回收，工作日志随主库逐步扩展，不初始化时预占整个预算。
- 保守预留意味着主库可用容量约为总预算一半，正文还需扣除索引等空间。每条写入前需完整256页/1MiB主库增长窗口及对应日志空间，不足在SQL前停采；SQL FULL始终视为存储故障，不猜测ENOSPC来源。降低预算不淘汰未到期记录，超额停采但可继续非增长维护。
- 预算暂停可以空间恢复，真实 I/O、ENOSPC、只读和完整性故障不得由提高预算解除。
- 新旧格式互开明确拒绝，保留现场；损坏数据库不自动重建，不删除旧文件。

## 验收

按用户后续明确授权，构建、依赖下载和运行验收仅在既有隔离 Linux 执行，本机只编辑源码；不执行 macOS 验收，也不声称该平台通过。沿用 docs/agents/verification.md 的实际系统、工具、浏览器、正式官方容器及适用磁盘故障验证，改写 JSONL 私有夹具，防止空扫描假通过。记录实际命令和未执行项，不以历史结果替代。

## 交付

提供已验证的正式插件路径、摘要和安装步骤；使用新的数据目录，重新发现和选择监控对象，不替换用户 CPA，不实际生产安装，不自动提交、推送或删除。
