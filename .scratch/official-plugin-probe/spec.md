# 官方插件版隔离验证

Status: completed

## 问题

在未经本项目补丁修改的 CLIProxyAPI v8.0.27 中，官方执行拦截接口是否足以支持值得维护的输入记录插件？本实验不修改正式插件、既有需求或 ADR，也不部署生产。

## 范围

固定项目基点 `6711c1cb7a08c432e8690e66c87a3a74ad752480`；官方宿主从 Git 对象 `bf9341629ef2300ac9d846a2e80fe2756f63a671` 全新导出。仅使用合成凭据和本地上游。

验证三协议 HTTP 的正文/身份、执行与提交标识、重试与嵌套执行、失败前后覆盖、普通与 Codex duplex WebSocket、管理保护和静态资源。每端同实例两轮，macOS 与隔离 Linux 使用同一份源码。探针仅保留有界摘要，不保存原请求、请求头或 Key。

## 判定

基础设施错误必须修复；确认的接口能力不足是实验结论，不冒充实现成功。分别回答是否可维持现有需求、是否值得做明确降低覆盖范围的官方插件版。结论由已发送、上游已接收与插件已观察的独立证据支撑。

## 实施

见 [01-official-probe](issues/01-official-probe.md)。本轮两端实际测量已完成，结论见 [验收记录](../../docs/verification/official-plugin-probe-2026-10-16.md)：官方插件可支持有范围限制的 HTTP 输入记录，不能等价替代现有四协议入站观察。本实验不修改正式需求。
