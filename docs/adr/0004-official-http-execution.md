# 使用官方执行拦截接口提供 HTTP 输入记录

2026-10-16，用户在完成原版 CPA 隔离实验后，选择无需宿主补丁的精简版。该决定替代 ADR-0001、ADR-0002、ADR-0003 中对当前产品的入站观察、读体前快照和 WebSocket 逐消息保证；旧文档及其真实验收记录作为历史保留。

## 决策

正式插件使用官方 C ABI / RPC schema 6 的 RequestInterceptor Before，以及已有管理注册接口。只记录三协议 HTTP/SSE 的外部执行输入，不修改请求、认证、模型路由或回复。After 原样放行，不依赖模型结果；官方 source=plugin_host_model_callback 的内部执行与 WebSocket 明确排除。

记录时间是回调观察时刻，模型是执行入口所见模型，不等同于客户端原始提交时刻/模型。一次官方执行 ID 对应一条记录，不用内容或 HTTP TraceID 猜测合并。HTTP 路由前失败等未到达回调的提交不可见，不能计算完整漏采数量。

## 身份和发现

原版不提供原补丁的完整匿名 Key 目录。插件对瞬时 caller_scope 使用私有随机种子和域分隔 HMAC 派生匿名 ID；仅保留有界已观察目录，管理员选择命名后才持久化监控对象。未监控不存正文，首次发现请求不会事后补录。只验证内置客户端 Key 环境，不将上游账号或任意请求头作为可信身份。

新身份格式与旧 raw-Key 派生对象不等价。新 seed 格式标记、权限与文件/目录同步属于初始化必需项；旧目录拒绝混用，不自动轮换种子、覆盖数据或做推断迁移。

## 为什么

隔离实验已在 macOS arm64 与 Linux amd64 证明常规 HTTP 正文、身份稳定性、重试执行 ID 和原版管理加载可用。也实际证明路由前失败不可见、Messages 模型已改写、普通 WS 补回历史、Codex duplex 后续 append/steer 无执行回调。后者不能通过插件内部推断恢复。

使用官方接口降低部署与升级负担：用户只需安装平台兼容的动态库、配置新持久目录，不必改造 CPA。代价是明确减少覆盖范围，而不是假装保留完整审计语义。不增加原版/补丁双模式，也不在本次引入额外代理服务。

## 保留与调整

保留正文最小化、异步有界队列、查询、预算、保留期、故障诊断、管理鉴权和纯文本界面。关键词搜索改 POST 正文，避免原版 URL 访问日志额外保存关键词。诊断只描述插件实际观察到的错误，页面持续说明未知覆盖范围。

## 验证

实施验收必须使用精确官方源码/固定镜像，而不是缓存中曾打补丁的工作树或旧产物。两端真实系统与浏览器检查验证新契约；旧 WS/入站快照用例逐项记为历史，不将移除保证解释为测试成功。实际结果另见本轮交付记录。
