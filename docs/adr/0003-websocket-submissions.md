# WebSocket 完整帧接收与逐提交快照

2026-10-15，ticket 07 将独立输入观察契约升级为 v3，保持 ABI 1 / RPC schema 6。观察位于 Responses 唯一 downstream reader 的完整 Text/Binary 消息接收之后、输入队列之前，而不是普通 handler 的 `response.create` 分支：Codex duplex 会直接消费同一队列，后续 `create`、`append` 和携带业务输入的 `steer` 绕过 handler 循环。在共同入口观察也使排队期间的配置变更、模型失败和客户端取消不改变已经接收的提交；消息前缀缺少终帧只能报告读取缺口，不能把完整 JSON 前缀当完整消息。

握手只将最终原生认证身份映射为不透明对象并绑定宿主私有提交工厂，不冻结采集资格、不保留额外 Key 副本。逐帧新建宿主提交标识和时间，重新取得监控、暂停及上限快照，再沿用原观察者实例投递；后续移除宿主 Key 仍按原连接认证行为处理，不为审计重新鉴权。相较于执行层观察或握手级快照，这避免历史恢复扩大采集范围和长连接配置失效；代价是每个完整应用消息都有一次同步、只读准备/观察调用，故障只产生固定诊断。

v3 明确要求四种输入协议能力齐备，并允许1–65536字节的快照上限。老 HTTP-only 契约不可静默降级。ticket 07 提前补齐管理设置中的单条上限子集，使用原配置持久化事务；不提前实现保留期或预算管理。旧配置默认64KiB，已保存正文继续按绝对64KiB上限读取，降低当前上限不改历史或已接收副本。
