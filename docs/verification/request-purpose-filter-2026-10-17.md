## 实际失败与修复

1. **旧产物确实复现用途未记录及辅助误存。** main 详情 purpose 为空；turn+subagent 和成功路由的 compact 输入仍被保存。修改后用途专项回归通过。
2. **新存储严格校验确实先失败再通过。** 显式空值、null、skip、非法枚举及未知字段拒绝；新旧混读、重启和保留期原行保留有独立测试。main 完整模板与未知用途旧行为分别验证。
3. **首次 macOS 全套因缺少固定 headless shell 停在启动阶段。** Node/curl 直连官方存储出现 TLS 重置；经用户明确授权，从既有隔离环境获取相同 Google 官方归档，校验后在独立目录运行 Chromium `156.0.8078.4`，未关闭 TLS 校验或修改全局配置。归档 SHA-256 为 `94e4337b70cbc5638f0935fbc46b9f242bc7416f657e3fbe924baf348404b53d`，未清理现有缓存。
4. **真实浏览器发现 CSP 摘要漏更新。** 新用途标签改变内联脚本，旧 CSP 令连接按钮无响应。先新增摘要回归观察失败，再更新 script SHA-256；style 限制不变，未使用 unsafe-inline。两轴限定复核均通过。
5. **两处旧浏览器断言不适应独立用途徽标。** 截断及 WS 场景把整个状态单元格精确等于内容标签；改为逐个精确匹配原有 badge，保留正文、协议与状态布尔断言。两个场景和用途查询均已各两轮通过。
6. **一次全套中既有详情请求超时。** `TestResponsesHTTPContent/literal` 等待详情超过原5秒。未增加超时或跳过；单独连续三轮通过，后续串行全套通过。不把失败轮当成通过，也未把未复现的超时归因为已证实的生产缺陷。
7. **Linux 新增首次发现用例缺少插件就绪条件。** 一轮 compact 用例首次读取状态不可用；原 raw 启动器仅等待根路径，而非插件管理接口。新增仅查询 `/status` 的有限就绪等待，不发送模型请求预热，不改原请求超时；其他 HTTP 错误和坏 JSON 立即失败。补充后本机连续三轮、Linux连续五轮通过，两端最终全套均通过，首次发现断言保持。
