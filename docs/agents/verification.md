# 验证与交付约定

本文件规定本项目的验证责任、审查范围和证据边界。可执行命令以根目录 `Makefile` 为准；当前宿主契约从 `host/manifest.json`、[当前 spec](../../.scratch/official-http-input/spec.md) 和 [ADR-0004](../adr/0004-official-http-execution.md) 读取，不再从旧 host patch 推导正式能力。

正式 HTTP 精简版的实际平台、UI、容器与故障结果见[交付记录](../verification/official-http-input-2026-10-16.md)。后续修改须独立验收，不能把镜像标签存在、探针结果或旧交付报告作为新版本通过的证据。

## 实施与验收

1. 实施开始记录当前 `HEAD` 作为固定审查基点，读取当前 ticket 和相关领域文档。本轮已固定基点为 `6711c1cb7a08c432e8690e66c87a3a74ad752480`，沿用用户指定的 `experiment/official-plugin-probe` 分支，不重新选基点或分支。
2. 宿主接入先定位 manifest 指定的官方契约与固定源码：CPA `v8.0.27` / `bf9341629ef2300ac9d846a2e80fe2756f63a671`，C ABI `1` / RPC schema `6`，官方 `RequestInterceptor` + `Management`。`make build` 必须从精确 Git 对象新导出官方 host、无 patch；安装路径另验 `make build-plugin` 仅构建动态库，不重编或替换用户 CPA。取得具体问题的证据即结束调查；已委派调查等待结果，其他执行者复用定位，不重复全库搜索。
3. 每张 ticket 都在本机 macOS 和既有隔离 Linux 环境验收**同一份最新源码**：快速检查、原生宿主/插件构建、真实系统测试、工具测试及涉及改动的浏览器场景。通常 Linux 入口为 `ssh linux-service`，沿用既有普通测试用户与隔离工具链，环境参考[历史 Linux 记录](../verification/linux-amd64-2026-10-15.md)，先核对实际环境，再建独立源码/结果目录。当前任务若禁止 SSH 或限定可改文件，严格遵守授权范围，未执行项留待有权限的主会话，不能声称双端完成。
4. 对当前契约逐项验收三协议 HTTP/SSE、一次执行身份、重试与同文重交、失败/取消、内部 source 排除及 WebSocket 排除；核对 Before 时间与可能改写的模型。不把回调前未知模型/路由/读体失败当作可见事件，不据零缺口声称完整覆盖。
5. 身份验收包括已认证 `caller_scope` 的私有域分隔 HMAC、有界匿名发现、默认不监控、首次发现不存正文、选择后采集、未选择重启丢失及已选择恢复。新 seed 必须在持锁空目录中安全初始化并持久化，旧 `identity.seed`、已有数据缺新 seed 和损坏 seed 均拒绝且保留；目录及 seed 不能被测试自动删除、迁移或轮换。
6. 验证 POST `/v0/management/plugins/request-input-audit/records/search` 的列表/筛选/关键词/分页与 GET 详情、管理鉴权、无数据公开 shell、纯文本展示、搜索词不进入 URL/访问日志，以及保留期、预算、诊断和故障回归。固定前端 `v1.26.2` 与 `MANAGEMENT_STATIC_PATH`、禁止自动更新一起验，不用原前端兼容结果替代本轮 UI 测试。
7. 容器使用固定官方镜像 `eceasy/cli-proxy-api:v8.0.27`，不自建 CPA 镜像。实际验证目标架构/libc、非 root 插件加载、独立 state 卷、采集和重启恢复；Dockerfile 路径或镜像标签存在只能证明安装前提，不能证明容器通过。记录实际镜像身份、运行用户与结果，未执行则明确保留未验证。
8. 每项记录命令、通过/失败/未执行和有限证据；失败修复后复测。异步等待本轮唯一标记或记录 ID 的已保存结果，在同一实例重复运行，避免历史数据冒充本轮结果。两端均完成本票必需验收后才标记 `completed`；跳过、无法执行或只构建成功不算完成。
9. 只把缺少权限、账号或确实无法自主操作的事项交给用户协助；已通过的技术检查不要求用户再做一遍。自主验收不包含未经授权的生产部署、凭据修改、删除或提交。

## 当前用例与历史用例

- 默认构建和验收使用固定官方宿主，不再构建私有 compat-overlay 或依赖 `build-compatibility-test`。保留期专用产物可使用插件内 `audittest` 时钟，不能把测试库安装到用户目录。
- `legacy_patched` 只保存旧入站快照、私有观察合同和 WebSocket 等历史用例，不作为正式版兼容模式，不批量 skip 后宣称兼容或全部通过。对已移出产品的保证逐项说明替代覆盖或当前不支持；仍保留的功能必须由当前官方契约用例实际验证。
- 旧 ADR-0001～0003、旧 spec、macOS/Linux 与票13报告保留原事实，不改写成新契约，也不复用其通过数。探针仅是决策证据，正式交付记录只写本轮实际命令和结果。

## 审查范围

个人 `code-review` 技能保持原样；在本项目调用时显式传入固定基点及以下范围说明，补足技能默认的仅已提交差异：

- **工作区实施审查**：`git diff <基点> --` 涵盖已提交后的实现、已暂存和未暂存差异，另以 `git ls-files --others --exclude-standard` 获取新文件。固定同一文件清单供 Standards/Spec 两轴使用，检查范围是否非空，不以 `<基点>...HEAD` 为空认定没有变更。
- **已提交审查**：`git diff <基点>...HEAD` 及相应 commit 清单；适用于分支或 PR。
- 两种范围均先核实基点可解析。用户已提供或实施开始已记录的基点直接使用，不重复询问。其他 worker 的变更属于工作区事实，不擅自覆盖、暂存、回退或删除。
- 修复后的复核限定原 finding 及相关变更，随后执行受影响回归，不重新展开完整源码调查。

## 提交与完成

- 按 `issue-tracker.md` 记录 `Status` 和 `Triage`；本票范围通过约定验收才标记 `completed`，不代表父 spec 或未运行平台已完成。任务禁止修改 `.scratch` 时由主会话更新，不越界代写。
- 本地 commit 仍需用户**独立明确授权**，提交前展示摘要并执行暂存检查。个人 implement 技能的默认提交步骤不能覆盖该约束；测试通过不等于获准提交。
- push、部署、删除、凭据和 CI/CD 修改分别遵循授权边界。不自动删除源码、状态、seed、卷、镜像或证据目录；回滚保留原镜像/配置及新旧状态。
- 最终报告包含实现、实际验证、未验证项、是否提交/推送。没有人工待办时明确说明；仍在其他 worker 运行的项目不得预报结果。

## 自动检查的边界

- 快速检查只查第一方 Go 格式、vet、测试编译，不启动模型宿主、浏览器或磁盘故障测试。缺少本地依赖时明确失败，依赖准备单独执行。
- 本仓库不提供 pre-commit hook。需要验证暂存内容时手动运行 `make check-staged`，检查真实 index 的隔离快照，不以工作树的未暂存修复掩盖提交问题。
- 系统/工具/浏览器按 `Makefile` 执行；浏览器通过本地 Playwright 驱动真实合成实例，不依赖 MCP。平台 skip 不记为通过；真实小卷 ENOSPC/只读重挂与队列满须有对应平台实际结果。
- Linux 小卷入口 `make verify-linux-disk` 需调用者明确提供权限与隔离参数，不由快速检查或默认 `make verify` 自动提权执行。只读重启不冒充运行中热切只读。
- 本项目在本机 macOS 及获准的既有隔离 Linux 环境验收，不维护远端 CI workflow，不以 push 触发测试；未运行平台明确标记未验证。
- 证据只保存有限结果和状态标签截图，不上传认证材料、完整输入、日志原文、审计数据目录或磁盘镜像。进程/挂载正常回收，文件保留，不自动删除。常规错误处理不代表 native 同进程崩溃已隔离。
