# 验证与交付约定

本文件规定本项目的验证责任、审查范围和证据边界。可执行命令以根目录 `Makefile` 为准；宿主接口以 `host/manifest.json`、补丁及 `docs/adr/` 为入口。

## 实施与验收

1. 实施开始记录当前 `HEAD` 作为固定审查基点，读取当前 ticket 和相关领域文档。
2. 宿主接入先定位清单/补丁给出的路径，再为未解决的具体问题扩大探索；取得证据即结束。委派的调查等待结果，其他执行者复用定位，不重复全库搜索。
3. 每张 ticket 都在本机 macOS 和既有 SSH Linux 环境验收同一份最新源码：快速检查、原生宿主/插件构建、真实系统测试、工具测试和涉及改动的浏览器场景。两端均完成本票要求的验收后才标记 `completed`；失败修复后复测，跳过或无法执行的必需项保留为未完成，不能以构建成功替代应用运行。Linux 使用 `ssh linux-service`，沿用已有普通测试用户与隔离工具链；环境入口及既有路径见 [Linux 验收记录](../verification/linux-amd64-2026-10-15.md)，先核对实际环境，再为每票创建独立源码/结果目录。
4. 每个验收项记录命令、通过/失败/未执行及有限证据。异步测试等待本轮唯一标记或记录 ID 的已保存结果，同一实例重复运行，防止误读历史数据。
5. 只把缺少权限、账号或确实无法自主操作的事项交给用户协助；已通过的技术检查不要求用户再做一遍。

## 审查范围

个人 `code-review` 技能保持原样；在本项目调用时显式传入固定基点及以下范围说明，补足技能默认的仅已提交差异：

- **工作区实施审查**：`git diff <基点> --` 涵盖已提交后的实现、已暂存和未暂存差异，另以 `git ls-files --others --exclude-standard` 获取新文件。固定同一文件清单供 Standards/Spec 两轴使用，检查这个范围是否非空，不以 `<基点>...HEAD` 为空认定没有变更。
- **已提交审查**：`git diff <基点>...HEAD` 及相应 commit 清单；适用于分支或 PR。
- 两种范围均先核实基点可解析。用户已提供或实施开始已记录的基点可直接使用，不再重复询问。
- 修复后的复核限定原 finding 及相关变更，随后执行受影响回归，不重新展开完整源码调查。

## 提交与完成

- 按 `issue-tracker.md` 记录 `Status` 和 `Triage`；本票范围通过约定验收才标记 `completed`，不代表父 spec 或未运行平台已完成。
- 本地 commit 仍需用户明确授权，提交前展示摘要并执行暂存检查。个人 implement 技能的默认提交步骤不能覆盖本项目授权约束。
- push、部署、删除、凭据和 CI/CD 修改分别遵循其授权边界。
- 最终报告包含实现、实际验证、未验证项、是否提交/推送。没有人工待办时明确说明。

## 自动检查的边界

- 快速检查只查第一方 Go 格式、vet、测试编译，不启动模型宿主、浏览器或磁盘故障测试。缺少本地依赖时明确失败，依赖准备单独执行。
- 本仓库不提供 pre-commit hook。需要验证暂存内容时手动运行 `make check-staged`，检查真实 index 的隔离快照，不以工作树的未暂存修复掩盖提交问题。
- 完整系统测试包含实际小卷 ENOSPC/只读重挂和队列满；浏览器入口通过本地 Playwright 驱动真实合成实例，不依赖 MCP。
- 本项目在本机macOS及既有SSH隔离Linux环境运行检查和验收，不维护远端CI workflow，不以push触发自动测试；未运行平台明确标记未验证。
- 证据只保存有限结果和状态标签截图，不上传认证材料、完整输入、日志原文、审计数据目录或磁盘镜像。进程/挂载正常回收，文件保留，不自动删除。
